# Resilience changelog

Every change agreed and applied to the resilience site, with the fingerprint that proves it is still there.

Check with `python3 tools/verify_changelog.py` — run it every five changes or so, and always before a release.

If an entry reads GONE, the working tree has rolled back past that change; re-apply it from the description and re-run.

An entry marked SUPERSEDED was deliberately replaced by a later change, which is named against it.

The archive of this record sits outside the tree, so a rollback that takes the changelog with it is still visible.

## How a check works

Each entry in `changelog.json` carries a `check` tested against the files: `contains`, `absent`, `regex`,
`band10`, `footers`, `count_files`. Fingerprints are the CSS comments and rules each change introduced.
